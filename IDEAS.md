## Хочется

### При загрузке фоток сразу выбирать, в какие ещё альбомы добавить
- Сейчас: загрузка идёт в один альбом (страница `#/album/<id>`), добавить в другой можно только потом через «add photos from another album».
- Идея: рядом с зоной загрузки чекбоксы/мультиселект других альбомов (из `lastAlbums`). После успешной загрузки каждого файла (или всей пачки) вызывать `POST album/<otherId>/files` с `{ name, ref }` для выбранных альбомов. Это metadata-only, ничего не копируется.
- Учесть: конфликты имён в целевых альбомах (409 + `conflicts`, спросить один раз про все), чанки по `PAGE_ATTACH_FILES` = 20, `invalidateAlbumCache()` уже делается в `putInfoJson`.
- Опционально: то же на форме «New album» (`#/new`): создать альбом и сразу указать, куда ещё положить фотки.

### Статистика / аналитика посещений
- Что хочется знать: сколько раз открывали альбом, когда последний раз, сколько уникальных посетителей, скачивания ZIP.
- Ограничения: публичный путь не должен листить R2 и не должен логировать секрет. Workers Free: 50 subrequests, 10 ms CPU, счётчики не должны замедлять `/api/album`.
- Варианты:
  1. **Workers Analytics Engine** (`[[analytics_engine_datasets]]`, `writeDataPoint` в `ctx.waitUntil`): точка на каждый успешный `POST /api/album/<id>` (blob: albumId, результат; index: albumId). Запрос через SQL API, показ в админке или в дашборде Cloudflare. Бесплатный тариф есть. Не считает уникальных без хеша IP.
  2. **Cloudflare Web Analytics** (beacon-скрипт): ноль кода на сервере, но нужно расширить CSP в `public/_headers` и данные видны только в дашборде Cloudflare, без разбивки по альбому в нашей админке.
  3. **Счётчик в `AlbumInfoDO`**: `{ views, lastViewAt }` рядом с кешом `info.json`, инкремент через `ctx.waitUntil`, выдача в `GET albums` для админки. Минимум инфраструктуры, но DO-хранилище ограничено и нет истории по дням.
- Склоняюсь к 1 (+ опционально 3 для быстрого «просмотров: N» в списке альбомов). Приватность: не хранить IP в открытом виде, секрет не логировать никогда.
